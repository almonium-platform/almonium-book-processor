1a Almonium mobile — system, screen map, first batch of screens, codebase audit
Almonium · mobile · v1

The app is the reader in your pocket

Same product, same laws, different ergonomics. The web app is where a session is planned; the phone is where the loop actually closes — reading in a queue, saving a word on a train, clearing ten cards before bed. Everything here obeys the design constitution; where the phone forces a different answer, the rule is stated rather than improvised.

Frames are 390×844 at 1×, so every size below is a literal iOS point value.
Scope: Expo / React Native client (almonium-mobile). Reference: design constitution v2, master brief.

What changes from web to phone

Ten rules. Nothing else about the constitution is renegotiated on mobile.

1 · Four tabs, and the fourth is the lookup. Home, Read, Review, Look up. Settings sits behind the avatar, notifications behind the bell, people behind settings. A tab is a place you go many times a day; nothing else earns one.
2 · The page header pattern survives, in content. Eyebrow → serif headline → one-line subhead → one action, scrolling with the page. No platform title bars, no large-title collapse, no duplicated screen name.
3 · Sheets, not modals. Every secondary surface is a bottom sheet with a 28px top radius and a grabber: the word sheet, sense picker, reader settings, marginalia, language switcher. Sheets are dismissible by drag, and never cover the sentence being read.
4 · One primary action, pinned above the safe area when the screen commits something (save, start, grade). No floating action button — a circle of plum hovering over prose is a different product's idiom.
5 · Type scale steps up. Reader 19/1.65, body 15, UI label 13, metadata 12, eyebrow 11 with 1.5px tracking. Nothing below 11. Serif for the word, the book and the sentence; sans for everything you tap.
6 · 16px gutters, 20–24px card radius, one card tier. On a 390pt screen a nested card inside a card wastes 64pt of width, so nested blocks become hairline-separated rows instead. Panels 24, rows and chips 12.
7 · The language rail moves under the app bar — 3px in the active language's hue, with the code badge sharing it. It is the only chrome that carries language colour, and the only way the user can see which language they are in.
8 · Gestures are conventional and few. Swipe back, long-press a word to select, drag to dismiss a sheet, pull to refresh a list. No swipe-to-grade in review: a mis-swipe writes a memory event you cannot see and cannot undo.
9 · Haptics are rationed like celebration. Light impact when a grade commits and when a word is saved. Success notification haptic on the three earned events only. Nothing on navigation.
10 · The native surface is the point. Push for due reviews, a share-sheet target that saves a word from any app, downloaded books that read offline, a lock-screen audio player. These are what the phone adds to the product, not a smaller copy of the web app.

Audit

What is wrong in almonium-mobile today

Read against constitution v2 and the master brief. The client is well built — typed API layer, real tests, sane theme file — and its problems are almost all decisions taken before the redesign. Blocking stops the loop or breaks a law. Fix is wrong but survivable. Tidy is bookkeeping.

BlockingThere is no lookup surface at all

No Discover route, no word sheet, no paste box. The app can read a book and drill existing cards, but the step between them — meet a word, understand it, keep it — does not exist on the phone. It is also the conversion mechanic and the only sensible target for a share extension. This is the single largest gap.

BlockingThe reader cannot save a word

app/reader/[bookId].tsx renders text and syncs position; selection leads nowhere. The missing reader-to-card connection is the product's known gap on web, and on mobile it is the whole product: reading on a phone is where words are actually met.

BlockingSeven tab routes for a four-surface product

(tabs)/_layout.tsx registers home, books, cards, play, settings, inbox and people; two are hidden with href:null and one, Play, is a tab for a feature the brief has parked until the core loop retains anyone. Settings is not a destination you visit several times a day, and “More” is what a product calls a tab when it has run out of thesis. Ship Home, Read, Review, Look up; move settings behind the avatar, notifications behind the bell, people behind settings.

Blockingcolors.reading = '#FF7F00'

An off-ramp orange, used for the reader bar, the shelf bars, home progress, the onboarding step bar and a settings icon. Law 1 allows no brand hue off the emblem's ramp, and status colours are the only exception — reading position is not a status. Reading progress is a plum linear bar; onboarding uses a labelled step plank; the icon takes ink. Delete the token and the sentence in the file header that justifies it.

BlockingScheduling is device-local

src/card-utils.ts and progress-utils.ts compute intervals on the handset. That makes sync a lie, makes the web and phone disagree about what is due, and makes due-review push — the biggest retention lever in the category and the thing Readlang structurally cannot ship — impossible, because the server does not know. Move to server FSRS before any further review work.

FixThe repo's visual instructions are the superseded ones

AGENTS.md names docs/Almonium design system analysis.md as the source of truth and instructs the next agent to use “the plum-to-raspberry gradient for the primary commit action”, treat “cyan-violet” as premium, use orange as a reading accent and 24–35px cards. Constitution v2 prohibits all four: gradient means premium and nothing else, cyan is banned outright, no hue lives off the ramp, panels are 24–28. Repoint it at the constitution and the master brief, and note that components/ui.tsx already gets the button right — the docs are more wrong than the code.

FixAvatars: photo uploads, and the wrong tier fill

components/avatar-picker.tsx uploads images to Firebase Storage and lists custom avatars. The constitution retires custom uploads — moderation, storage, GDPR deletion and cropping cost more than a barely-social profile returns. One disc, one fill, and the fill is the tier. Premium is currently flat raspberry in people.tsx and profile/[userId].tsx; it should be the premium gradient with a cream mark, free flat #d8cfd6 with an ink mark, and nothing else encoded. Settings shows a third variant, a plum rounded square with a sans letter.

FixCards, not items; one intent, not five

Routes are card/[cardId], card/new, and the tab named “Review” is the file cards.tsx. src/types.ts has no learning intent, no sense, no encounter and no confusion edge, so the second and first most defensible ideas in the product cannot be expressed on the client. Rename to LearningItem alongside Card, and add intent before designing more review screens — three of the card types in the map depend on it.

FixNo theme layer, so no dark reader

src/theme.ts is a flat const consumed as literal hexes at every call site. The constitution requires authoring against tokens and one flip for dark, and dark reading is the top mobile expectation — people read in bed. Introduce a token provider with a dark set that extends the ramp at its light end (#E0C4EE, #CBA3E0, #B07BD0, #9059BC, rose #D98BA8) and elevate by lightness plus hairline, not shadow.

FixNothing native is used

No push, no share extension, no offline download, no audio session, no widget. The app is currently a smaller mirror of the web client, which is the one thing a native app should not be — those four capabilities are the entire argument for building it. Push and share-sheet save are the two that pay for themselves immediately.

FixOnboarding sells a plan and mentions games

onboarding.tsx describes the free plan — “one target language, daily reading, flashcards, and basic games”. The constitution removed the paywall step from onboarding entirely, and games are parked, so the line advertises something that will not be there. Cut it; the ask belongs at the wall. Also missing: the level ladder for “I'm not sure”, and Almo's greeting as the final screen instead of a form.

FixPlatform headers instead of the page header pattern

Tabs are configured with expo-router headers and a semibold sans title, which reproduces the screen name and leaves no room for the eyebrow → serif headline → subhead → one action pattern the rest of the product uses. Set headerShown:false and own the header in content. The same change is what makes room for the language rail, which currently does not exist anywhere in the app — in a multi-language product the user cannot see which language they are in.

FixPaywall is a screen, not a wall

membership.tsx plus a generic paywall-modal with a features list. Placement is meant to be contextual — second language, hundred-and-first item, audio tap, custom import — with copy specific to the boundary reached. Keep the plan screen for management. Note that in-app purchase must go through StoreKit and Play Billing, not Paddle; that is store policy, not a preference, and it needs pricing parity work.

TidyRadii, off-ramp tints, and Alert.alert as an error surface

radii.card = 30 is outside the 24–28 panel range and inline = 8 is below the 12–18 nested range. accentSoft #F8EAF3 and accentBorder #E9CADF are undeclared tints — either derive them from the ramp or name them in the constitution. And a dozen failure paths end in a system Alert.alert, which is the one component in the app with none of the product's voice in it.

Suggested order

Tabs down to four and the orange token deleted (an afternoon each) → the word sheet, reachable from the reader and a new Look up tab → server FSRS → due-review push → intents, then the four remaining card types → token layer and the dark reader → share extension and offline downloads. Everything in group F stays untouched until a stranger has completed the loop three times.
